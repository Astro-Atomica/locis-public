# Getting started with loc.is

Updated October 7, 2026 · Build 2

Open [loc.is](https://loc.is/) and use the search field for a place name, address, latitude/longitude pair, location code or location link. The [website guide](https://loc.is/s/how-to.html) explains the available inputs and controls.

A location link identifies an encoded rectangle. For example, [loc.is/38MC3A](https://loc.is/38MC3A) is a public example location. Share only the detail you intend to reveal: anyone receiving a location link can decode its area.

Search results for named places can use source extents or estimates. Those inputs, the selected location rectangle and a real-world administrative boundary are different things. Use the [place atlas](https://loc.is/s/boundaries.html) to inspect the site's experimental place representations. Do not use a code as evidence of a legal boundary or precise entrance.

For embedding links or building an integration, use the [web developer section](https://loc.is/s/how-to.html#web-developers). Automated clients should also read the [agent guide](https://loc.is/s/for-agents.html). These public guides are the reference for current visitor-facing behavior; this repository does not declare a frozen addressing standard.

If a page, map, location result or explanation appears wrong, follow [Reporting issues](reporting-issues.md). The [privacy page](https://loc.is/s/privacy.html) explains location processing and visitor choices; the [AI policy](https://loc.is/s/ai-policy.html) explains assistance, prepared data and review requirements.

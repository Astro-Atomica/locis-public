# Privacy and safe location sharing

Updated October 7, 2026 · Build 1

A loc.is link and its QR code reveal an encoded area to anyone who receives them. Choose the geographic detail you intend to disclose before copying a link or posting a screenshot.

## Choose a suitable area

For a public profile, consider a wider area rather than a home or workplace. For an event, share a public venue and retain entrance or landmark directions. Check every link before distributing it. Removing a place name does not hide an area still encoded in a visible link or QR code.

The homepage's IP-based location is approximate. Sharing device location uses the browser's permission flow and can provide a closer match, but you still need to check the result. The authoritative [privacy page](https://loc.is/s/privacy.html) explains providers, processing and current controls.

## Visitor choices

The public how-to guide describes these choices:

| Choice | Documented behavior |
| --- | --- |
| Lurk | Explore without a persistent visitor ID or visit tracking. |
| Remember Me | Save an anonymous browser ID and basic humanity signals. |
| Help the Site | Add visit statistics and optional lookup caching. |

Use the homepage choice or **Fine-tune** in its footer to adjust preferences. Consult the current privacy page for the detailed processing policy; these labels are not a claim that outside map providers receive no requests.

## Report problems safely

Public GitHub issues and attachments can be read by others. Reproduce a bug with a harmless public landmark where possible. Remove personal coordinates, private addresses, visitor IDs, cookies, tokens and account details. Inspect screenshots for private tabs and visible location codes. Do not upload unreviewed network captures or browser exports.

Follow [Reporting issues](reporting-issues.md) for ordinary problems. For vulnerabilities or details that cannot safely be made public, use [SECURITY.md](../SECURITY.md).

# Security and sensitive reports

Updated October 4, 2026 · Build 1

Email [hello@astroatomica.com](mailto:hello@astroatomica.com) with a subject beginning **LOCIS security** for a vulnerability or a report that includes sensitive information. This is the project's existing public contact address; no response deadline or bounty is promised.

Do not post vulnerability details, credentials, precise personal locations or visitor/account data in a public issue. Send a short description of the affected feature, potential impact and safe reproduction steps. Include only the minimum information needed; do not send secrets, another person's data or unredacted browser/network exports.

Keep investigation bounded to systems you control or have explicit permission to test. Do not exploit the live service, access other visitors' data, flood endpoints or inflate analytics. A harmless local example is preferable where it demonstrates the issue.

Coordinate public disclosure with a maintainer before posting technical exploit details. Ordinary bugs that can be safely described belong in the [public issue forms](https://github.com/Astro-Atomica/locis-public/issues/new/choose).

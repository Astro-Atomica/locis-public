# Public documentation and publication rules

Updated October 4, 2026 · Build 1

The [LOCIS AI usage policy](https://loc.is/s/ai-policy.html) is the project commitment. This repository's public documentation, issue prompts and support explanations are within its scope.

All AI-generated text requires human editorial review before publication. Record the actual reviewer and evidence tied to the reviewed version in ignored private notes. A generic setup instruction, automated check, another model or an agent's review is not approval of new wording. Prepare and validate local drafts while review remains pending; do not push that text publicly until the required review is recorded.

For new/revised documents, use a visible revision date and a per-document build number, starting at Build 1 and incrementing with each content revision. Dates and build numbers identify versions; they do not certify review.

Do not invent factual place information, permissions, paid work, engineer review or deployed behavior. Keep source geography, provisional AI-assisted data and deterministic rectangles distinct. Link canonical public guides rather than silently redefining code syntax. Any artwork needs truthful provenance, permission for the intended use and each AI operation, appropriate AI disclosure, and the human review required by the policy. Do not import unreviewed artwork into this support repository.

Publication includes pushing documents or forms to a public repository. Inspect the exact file set, staged content, Git identities and relevant history/refs before publishing. Run the privacy preflight and resolve findings within the approved policy; do not weaken checks to make the scan pass. Public reports must exclude visitor data, private paths, credentials, internal exploit details and contributor correspondence.

Keep review evidence and private records outside published content. Handoffs should state sources, validation, human review actually completed and remaining requirements. No artwork, runtime inference or visitor data-flow change is sufficient context for an ordinary documentation-only setup, where accurate.

# Reporting issues

Updated October 4, 2026 · Build 1

Search [existing issues](https://github.com/Astro-Atomica/locis-public/issues) before [opening a report](https://github.com/Astro-Atomica/locis-public/issues/new/choose). If an existing report matches, add the information needed to reproduce your case.

Choose the closest form:

- **Website bug:** broken controls, loading problems, layout, accessibility, location links or QR behavior.
- **Place or location-data problem:** an incorrect name, source extent, map representation or fitted area. Explain which representation looks wrong; a code rectangle is not automatically an administrative boundary.
- **Documentation correction:** an inaccurate, unclear or missing explanation, or a broken documentation link.

Include the affected page URL or a harmless example code, the steps you took, what you expected and what happened. For website problems, browser/device details and visible error text help. Include the document's date/build if one is shown; do not guess an unavailable website version.

For place-data problems, explain the discrepancy and include a reliable source or your observations when available. A source is helpful but is not required to report something that needs investigation. Say when a claim has not been checked.

## Keep public reports safe to share

Reports, pasted text and attachments are public. Do not include home/work coordinates, live device location, private addresses, visitor IDs, authentication tokens, cookies, account details or unreviewed network/browser exports. A location URL and a QR code can reveal the same encoded area; cropping a screenshot does not redact a visible code or link.

Use a public landmark or another harmless location to reproduce the problem where possible. Review screenshots and remove private tabs, browser/account details and precise personal locations. Describe the issue without an attachment when that is sufficient.

For security vulnerabilities or a report that cannot be safely described publicly, follow [SECURITY.md](../SECURITY.md). Avoid testing an exploit against the live service or generating artificial traffic to demonstrate a bug.
